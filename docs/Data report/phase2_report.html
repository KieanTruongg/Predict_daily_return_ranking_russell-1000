S3 — Look-ahead Bias Check ✅ PASS
Script: scripts/05_eda/sanity_check_in_sample.py
Input: in_sample/returns.parquet + in_sample/forward_returns.parquet
Output: Console — xác nhận không có look-ahead

Mục đích

Look-ahead bias là lỗi nghiêm trọng nhất trong quant research: nếu target variable (forward_return) chứa thông tin tương lai tại thời điểm model predict, back-test sẽ giả tạo tốt nhưng live trading sẽ thất bại.

Phải xác nhận: forward_return[t] = return[t+1] — tức là model tại ngày T chỉ biết data đến ngày T, và target là return của ngày T+1.

Logic & Code

returns         = pd.read_parquet("in_sample/returns.parquet")
forward_returns = pd.read_parquet("in_sample/forward_returns.parquet")

# Tính lại forward return từ returns: fwd[t] = ret[t+1]
computed_fwd = returns.shift(-1)

# Đếm số cells khác nhau (phải = 0)
diff = (forward_returns - computed_fwd).abs()
diff_nonzero = (diff > 1e-10).sum().sum()
# Phải = 0 (ngoại trừ NaN shift boundary)

Kết quả

forward_return[t] = return[t+1] — exact match trên toàn bộ 6,021 ngày × 2,852 tickers.

Max diff = 0.00000000. Số cells không khớp: 0.

✅ PASS — Không có look-ahead bias. Target variable sạch, an toàn để dùng làm label cho ML model.

Mục đích

Phát hiện cổ phiếu có nhiều ngày liên tiếp với volume = 0. Volume = 0 sẽ gây chia cho 0 khi tính Amihud Illiquidity (|ret|/dollar_vol) và VWAP.

Logic & Code

volume = pd.read_parquet("in_sample/volume.parquet")

def max_consecutive_zeros(series):
    # Đếm streak dài nhất của 0
    is_zero = (series == 0)
    streaks = is_zero.groupby((~is_zero).cumsum()).sum()
    return streaks.max() if len(streaks) > 0 else 0

# Áp dụng cho từng ticker, lấy top 10 dài nhất
zero_vol_tickers = volume.apply(max_consecutive_zeros)
top10 = zero_vol_tickers.nlargest(10)

S7 — adj_close ≡ close ⚠️ WARNING (Design)
Script: scripts/05_eda/sanity_check_in_sample.py
Input: in_sample/close.parquet + in_sample/adj_close.parquet
Output: Console — ratio adj_close/close cho dividend-paying stocks

Mục đích

Kiểm tra adj_close có khác close không. Trong data thông thường (Yahoo Finance, Bloomberg), adj_close ≠ close vì adj_close điều chỉnh thêm dividend. Nếu adj_close = close, có 2 lý do: (1) không có dividend, hoặc (2) QC đã bake dividend vào close.

Logic & Code

close     = pd.read_parquet("in_sample/close.parquet")
adj_close = pd.read_parquet("in_sample/adj_close.parquet")

# Kiểm tra tỷ lệ adj_close/close cho dividend stocks
# KO, PEP, JNJ, MMM, XOM là dividend aristrocrats
dividend_stocks = ['KO', 'PEP', 'JNJ', 'MMM', 'XOM']
for t in dividend_stocks:
    ratio = (adj_close[t] / close[t]).dropna()
    # Nếu QC đã bake dividend: ratio = 1.000 cho mọi ngày
    # Nếu chưa bake: ratio sẽ drift dần theo thời gian (<1.0)

Kết quả

Cho tất cả tickers kiểm tra (kể cả KO Coca-Cola — dividend yield ~3%/năm):

adj_close / close = 1.000000 — exact, không có drift.

Phân tích

QuantConnect SplitAdjusted mode đã bake dividend adjustment vào close. Điều này có nghĩa:

  • close = Fully adjusted price (split + dividend)
  • adj_close = Duplicate của close (không có thông tin thêm)
  • → Chỉ cần dùng close trong Feature Engineering

# Winsorize cross-sectional (tránh outlier ±1364%)
def _cs_winsorize(df, lo=0.01, hi=0.99):
    q_lo = df.quantile(lo, axis=1)
    q_hi = df.quantile(hi, axis=1)
    return df.clip(lower=q_lo, upper=q_hi, axis=0)

# Volume = 0 → NaN guard (tránh chia cho 0)
vol_clean = volume.replace(0, np.nan)

# Momentum (winsorized compound return)
log_ret  = np.log1p(ret_w.fillna(0))
roll_sum = log_ret.rolling(d, min_periods=max(1, d//2)).sum()
features[f"ret_{d}d"] = np.expm1(roll_sum)

# Amihud Illiquidity
dollar_vol   = close * vol_clean
amihud_daily = ret_w.abs() / dollar_vol.replace(0, np.nan)
features["amihud_20d"] = amihud_daily.rolling(20, min_periods=10).mean() * 1e6

# CS Rank features
features["ret_1d_rank"] = features["ret_1d"].rank(axis=1, pct=True, na_option="keep")

Mục đích

Đánh giá Rank IC (Information Coefficient) của: (1) Alpha Benchmark Reversal 5D theo công thức thầy, và (2) Tất cả 23 features trong Feature Store. IC = Spearman correlation giữa signal rank và forward return rank, tính cross-sectionally mỗi ngày.

Ngưỡng IC thực tế: Mean IC > 0.03 (Tốt) | 0.01–0.03 (Yếu có) | <0.01 (Rất thấp) | ICIR >0.5 (Solid)

Reversal 5D — Công thức thầy

# Công thức: α_i = (P_{t-5} - P_{t-1}) / 5, sau đó demean cross-sectionally
p_t5  = close.shift(5)   # P_{t-5}: giá 5 ngày trước
p_t1  = close.shift(1)   # P_{t-1}: giá ngày hôm qua
raw   = (p_t5 - p_t1) / 5.0

# CS demean → dollar-neutral (sum của alpha trên cross-section = 0)
alpha = raw.sub(raw.mean(axis=1), axis=0)

# Vectorized Rank IC computation
def compute_ic_vectorized(signal, fwd, method="spearman"):
    sig_r = signal.rank(axis=1, pct=True)
    fwd_r = fwd.rank(axis=1, pct=True)
    sig_dm = sig_r.sub(sig_r.mean(axis=1), axis=0)
    fwd_dm = fwd_r.sub(fwd_r.mean(axis=1), axis=0)
    n = (~signal.isna() & ~fwd.isna()).sum(axis=1)
    cov = (sig_dm * fwd_dm).sum(axis=1, skipna=True) / n
    return cov / (sig_r.std(axis=1) * fwd_r.std(axis=1))

💡 1. close_to_high là feature mạnh nhất (IC = +0.019)
Định nghĩa: (High − Close) / (High − Low) = 0 nếu đóng cửa tại đỉnh, 1 nếu đóng cửa tại đáy.
Ý nghĩa: Cổ phiếu đóng cửa gần đáy ngày (bị áp lực bán cuối ngày) → có xu hướng tăng ngày hôm sau. Đây là intraday reversal effect (Heston et al. 2010). ICIR = 0.169 — ổn định nhất trong tất cả features.
⚠️ 2. ret_1d có IC = −0.014 (ÂM mạnh nhất)
Cổ phiếu tăng hôm nay → giảm ngày mai (mean-reversion rất ngắn hạn). Phải đảo dấu khi dùng: feature = −ret_1d → IC equivalent = +0.014. Tương tự: −ret_2d, −ret_5d, −close_to_vwap_5.

Illiquidity premium không tồn tại trên Russell 1000 large-cap. Lý do: tất cả R1000 stocks đều liquid ($179.5M/day avg). Amihud effect chỉ được ghi nhận trên small-cap/micro-cap. Bỏ feature này khỏi ML model.

Kết luận về IC — Trung thực

Tất cả single-feature IC đều dưới 0.02 — đây là thực tế của US large-cap equity, không phải lỗi. Trong quant research, ngưỡng IC = 0.03 là "tốt" nhưng chỉ đạt được với mid/small cap, alternative data, hoặc factor combinations.

Giá trị thực của ML model đến từ:

  • Kết hợp nhiều weak signals (ensemble effect) — IC cộng dồn khi features không hoàn toàn correlated
  • Non-linear interactions — LightGBM bắt được interaction giữa features mà linear model không thể
  • Regime detection — model học khi nào feature nào work tốt hơn

Hạn chế thực tế (Trung thực)

  • IC không ổn định theo thời gian (ICIR < 0.2 cho hầu hết features) → Walk-Forward CV bắt buộc, không được dùng static train/test
  • Chỉ có price/volume data — thiếu earnings revision, analyst sentiment, short interest, macro variables
  • Feature store 1.1 GB → cần chunking khi train (Kaggle 30GB RAM)
  • Reversal effect suy giảm theo thời gian: 2001 IC=+0.028, 2023 IC=+0.001 — thị trường hiệu quả hơn, HFT làm mòn signal
  • Không có regime detection trong Phase 2 — Phase 3 cần thêm regime feature (VIX level, CS dispersion) vào model
